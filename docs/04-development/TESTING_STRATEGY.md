# テスト戦略

> このドキュメントは、多数のユニット/E2E テスト（カバレッジ閾値 80%+）の背景にあるテスト設計方針を説明します。実数の確認方法は下記「現在のテスト構成」を参照してください。
> テストの実行コマンドは [DEVELOPMENT_GUIDE.md](./DEVELOPMENT_GUIDE.md)、テストの方針は本書を参照してください。

---

## テストの目的

テストは「動作確認」ではなく「変更の安全網」です。

顧客がこの環境を引き受けた後、コードを変更するたびに「壊れていないか」を確認できること。これがテストの最大の価値です。

---

## テストピラミッド

```
        ┌───────┐
        │  E2E  │  少数 — クリティカルパスのみ
       ┌┴───────┴┐
       │  統合    │  中程度 — API エンドポイント全体
      ┌┴─────────┴┐
      │  ユニット  │  最多 — Service / Controller / コンポーネント
      └───────────┘
```

下層ほど高速・安定・大量。上層ほど低速・不安定リスクあり・少数。

## 現在のテスト構成

> 件数はモジュール追加のたびに増えるため、本ドキュメントでは概数（百件単位）に留める。正確な実数は下記コマンドで取得する（実数の二重管理を避け drift を防ぐため）。
>
> - バックエンド: `pnpm --filter @struct-pass/backend test`（ユニット）/ `pnpm --filter @struct-pass/backend test:e2e`（E2E、DB 起動が前提）
> - フロントエンド: `pnpm --filter @struct-pass/frontend test`

### バックエンド（Jest）

| 種別           | 件数（概数） | 対象                                                                |
| -------------- | ------------ | ------------------------------------------------------------------- |
| ユニットテスト | 800 件超     | Service, Controller, Guard, Interceptor, Filter, Mapper, Repository |
| E2E テスト     | 百件超       | API エンドポイント全体（認証、CRUD、権限検証）                      |

**テストファイルの配置**:

- ユニット: `src/**/*.spec.ts`（テスト対象と同じディレクトリ）
- E2E: `test/**/*.e2e-spec.ts`（プロジェクトルートの test/ ディレクトリ）

### フロントエンド（Vitest）

| 種別           | 件数（概数） | 対象                                         |
| -------------- | ------------ | -------------------------------------------- |
| ユニットテスト | 770 件超     | コンポーネント, hooks, utils, バリデーション |

**テストファイルの配置**:

- `src/__tests__/**/*.test.tsx`（**tests** ディレクトリに集約）

カバレッジ閾値は各 package の設定（backend: `package.json` の `jest.coverageThreshold`、frontend: vitest 設定）を source-of-truth とする。

## カバレッジ方針

### 閾値: 80%

```json
// packages/backend/package.json
"coverageThreshold": {
  "global": {
    "branches": 80,
    "functions": 80,
    "lines": 80,
    "statements": 80
  }
}
```

80% を下回ると CI が失敗します。

### なぜ 80% か

- **100% は現実的ではない** — 達成コストが急激に上がり、テストの保守負担が増える
- **60% では不十分** — 主要なパスがカバーされず、変更の安全性が担保できない
- **80% はバランス点** — 主要なビジネスロジックとエッジケースをカバーしつつ、過剰なテストを避ける

### カバレッジの4指標

| 指標           | 意味                     | 重視度                             |
| -------------- | ------------------------ | ---------------------------------- |
| **Statements** | 実行された文の割合       | 基本指標                           |
| **Branches**   | if/else 等の分岐カバー率 | 最重要（エッジケースの漏れを検出） |
| **Functions**  | 呼び出された関数の割合   | デッドコード検出に有効             |
| **Lines**      | 実行された行の割合       | Statements と概ね同じ              |

## テストの書き方の方針

### TDD サイクル

```
1. テストを書く（RED）  — 期待する動作を定義
2. テストが失敗することを確認
3. 最小限の実装を書く（GREEN）
4. テストが通ることを確認
5. リファクタリング（IMPROVE）
```

### バックエンドのテストパターン

**Service のユニットテスト**:

- Prisma をモック化し、DB に依存しない
- ビジネスロジック（バリデーション、計算、状態遷移）を検証
- エラーケース（Not Found、権限不足、重複）を網羅

**Controller のユニットテスト**:

- Service をモック化
- リクエストの受け取り・レスポンスの返却を検証
- Guard / Interceptor の適用を確認

**E2E テスト**:

- 実際の DB（テスト用）に接続
- HTTP リクエスト → レスポンスの全体フローを検証
- 認証トークンの取得 → API 呼び出し → レスポンス検証

### フロントエンドのテストパターン

**コンポーネントテスト**:

- レンダリングの確認（必要な要素が表示されるか）
- ユーザー操作のシミュレーション（クリック、入力、送信）
- API モックを使った非同期処理の検証

**hooks テスト**:

- renderHook で独立してテスト
- 状態変更の検証

**バリデーションテスト**:

- Zod スキーマの正常値・異常値を網羅

## テストを変更する場合のガイド

| 状況                 | 方針                                                                              |
| -------------------- | --------------------------------------------------------------------------------- |
| **新機能追加**       | テストを先に書く（TDD）。既存テストは変更しない                                   |
| **バグ修正**         | まず再現テストを書く。テストが RED になることを確認してから修正                   |
| **リファクタリング** | 既存テストを変更しない。テストが GREEN のまま完了すれば、動作が変わっていない証拠 |
| **仕様変更**         | テストを先に修正（新仕様を反映）。テストが RED → 実装を修正 → GREEN               |

### テストを消してはいけない場合

- カバレッジを上げるために別のテストに書き換える場合以外
- 「テストが邪魔だから」という理由で消すのは禁止

### テストを消してよい場合

- テスト対象の機能自体が削除された場合
- 重複するテスト（同じ動作を複数のテストで検証している場合）の整理

## テスト実行コマンド

```bash
# バックエンド
pnpm --filter @struct-pass/backend test          # ユニットテスト
pnpm --filter @struct-pass/backend test:cov      # カバレッジ付き
pnpm --filter @struct-pass/backend test:e2e      # E2E テスト

# フロントエンド
pnpm --filter @struct-pass/frontend test         # ユニットテスト
pnpm --filter @struct-pass/frontend test:cov     # カバレッジ付き

# 全パッケージ
pnpm test                                        # 全ユニットテスト
pnpm test:cov                                    # 全カバレッジ
```
