## 機能概要

未来の入荷・出荷予定を加味した予測在庫を表示し、余剰在庫や欠品リスクを可視化する機能。現在の在庫数に対して、指定期間内の入荷予定数を加算し、出荷予定数を減算することで将来の在庫状況を予測する。欠品リスク（予測在庫 ≤ 0）や余剰在庫（予測在庫 > 現在庫 × 3）をアラート表示することで、発注タイミングや在庫調整の判断を支援する。

**主な用途:**

- 欠品リスクの早期検出
- 余剰在庫の可視化
- 発注計画の立案支援
- 倉庫別の在庫バランス確認

## 画面レイアウト

**上部: フィルタエリア**

- 倉庫選択（プルダウン）、予測期間選択（1週間 / 2週間 / 1ヶ月）、アラートのみ表示（チェックボックス）、商品カテゴリ選択、検索ボタン

**中部: 一覧テーブル**

- ヘッダ: 倉庫名 / 商品コード / 商品名 / 現在庫数 / 入荷予定数 / 出荷予定数 / 予測在庫数 / アラート
- ソート機能: 商品コード、予測在庫数、アラートでソート可能
- アラート列: 欠品リスク（赤）、余剰（黄）、正常（緑）をアイコン表示

**下部: 操作エリア**

- ページネーション（前へ / 次へ / ページ番号）
- 表示件数選択（20 / 50 / 100件）
- CSV出力ボタン
- 発注画面へ遷移ボタン（欠品リスク商品を自動入力）

**アラート表示:**

- 欠品リスク（予測在庫 ≤ 0）: 行全体を赤背景 + 「⚠ 欠品リスク」アイコン
- 余剰（予測在庫 > 現在庫 × 3）: 行全体を黄背景 + 「⚠ 余剰」アイコン
- 正常: 通常表示 + 「✓ 正常」アイコン

## 予測ロジック

**予測在庫の計算式:**

```
予測在庫数 = 現在庫数 + 入荷予定数 - 出荷予定数
```

**入荷予定数の算出:**

- 予測期間内（今日から+N日）の入荷データ（receivings）を集計
- ステータスが `ordered` または `partially_received` の入荷予定のみ対象
- 集計対象: `receiving.expected_date <= 今日 + 予測期間`

**出荷予定数の算出:**

- 予測期間内（今日から+N日）の出荷データ（shipments）を集計
- ステータスが `pending` または `partially_shipped` の出荷予定のみ対象
- 集計対象: `shipment.scheduled_date <= 今日 + 予測期間`

**アラート判定ルール:**

1. **欠品リスク（赤）**: 予測在庫数 ≤ 0
2. **余剰（黄）**: 予測在庫数 > 現在庫数 × 3
3. **正常（緑）**: 上記以外

**予測期間:**

- 1週間: 今日 + 7日
- 2週間: 今日 + 14日
- 1ヶ月: 今日 + 30日

## 操作機能

### 1. CSV出力

- 現在のフィルタ条件に一致する全データを出力
- ファイル名: `forecast_stock_YYYYMMDD_HHmmss.csv`
- 出力項目: 倉庫名, 商品コード, 商品名, カテゴリ, 現在庫数, 入荷予定数, 出荷予定数, 予測在庫数, アラート
- 最大出力件数: 10,000件

### 2. 発注画面へ遷移

- 欠品リスク商品を自動で発注入力画面（D-1）に渡す
- クエリパラメータで商品IDリストを渡す: `/orders/new?product_ids=10,11,12`
- 発注画面で欠品リスク商品の発注数量を入力支援

### 3. 詳細表示（行クリック）

- 商品別の入出荷予定詳細をモーダル表示
- 入荷予定: 予定日、数量、ステータス
- 出荷予定: 予定日、数量、ステータス

## API

| メソッド | エンドポイント                              | 説明                                               |
| -------- | ------------------------------------------- | -------------------------------------------------- |
| GET      | /api/v1/stocks/forecast                     | 予測在庫一覧取得（フィルタ・ページネーション対応） |
| GET      | /api/v1/stocks/forecast/export              | CSV出力用データ取得（全件）                        |
| GET      | /api/v1/stocks/forecast/:product_id/details | 商品別入出荷予定詳細取得                           |

**リクエスト例（一覧取得）:**

```
GET /api/v1/stocks/forecast?warehouse_id=1&period=7d&alert_only=true&page=1&limit=50
```

**クエリパラメータ:**

- `warehouse_id`: 倉庫ID（オプション。未指定で全倉庫）
- `period`: 予測期間（7d, 14d, 30d）（デフォルト: 7d）
- `alert_only`: アラートのみ表示（true/false）（デフォルト: false）
- `category`: 商品カテゴリ（オプション）
- `keyword`: 商品コード/商品名の部分一致検索（オプション）
- `page`: ページ番号（デフォルト: 1）
- `limit`: 表示件数（デフォルト: 50）
- `sort`: ソート項目（code, forecast_qty, alert）（デフォルト: alert）
- `order`: ソート順（asc, desc）（デフォルト: desc）

## エラーハンドリング

| エラー条件         | メッセージ                                             | 挙動                              |
| ------------------ | ------------------------------------------------------ | --------------------------------- |
| 倉庫IDが存在しない | 「指定された倉庫が見つかりません」                     | 404エラー。フィルタをリセット     |
| 予測期間が不正     | 「予測期間は7d、14d、30dのいずれかを指定してください」 | 400エラー。デフォルト（7d）に戻す |

| CSV出力件数超過    | 「出力可能な最大件数（10,000件）を超えています」       | 400エラー。エラーダイアログ表示   |
| サーバーエラー     | 「予測在庫の計算中にエラーが発生しました」             | 500エラー。エラー通知を表示       |
| ネットワークエラー | 「通信エラーが発生しました。再読み込みしてください」   | 接続エラー。再読み込みボタン表示  |

**ツールチップ:**

**レスポンシブ対応:**

- モバイル表示時はテーブルをカード形式に切替

- アラートアイコンに `aria-label` を付与

## ビジネスロジック補足

**欠品リスクの定義:**

- 予測在庫 ≤ 0: 予測期間内に在庫が枯渇する可能性が高い
- 発注リードタイムを考慮し、早めの発注を推奨

**余剰在庫の定義:**

- 予測在庫 > 現在庫 × 3: 現在の3倍以上の在庫が予測される
- 保管コスト増加や賞味期限切れリスクを警告

**予測精度の向上:**

- 将来的には過去の入出荷実績から需要予測を機械学習で算出（Phase 6以降）
- 現在は単純な予定ベースの計算のみ
