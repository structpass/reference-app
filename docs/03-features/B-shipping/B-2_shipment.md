---

## 機能概要

商品の出荷情報を伝票形式で入力・管理する機能。顧客への商品出荷時に、出荷予定数量と実績数量を記録し、確定時に在庫テーブルから減算する。下書き保存→確定→出荷完了の3段階ステータス管理により、出荷業務のフローを管理する。在庫不足時は警告表示するが、出荷処理自体は続行可能。

**主な用途:**

- 顧客への商品出荷時の出庫処理
- 出荷予定と実績の差異管理
- 倉庫別在庫の自動更新
- 運送会社別の出荷管理

**画面構成要素:**

1. ヘッダフォーム（出荷伝票全体の情報）
2. 明細行テーブル（出荷する商品の明細）
3. 在庫不足警告エリア（該当商品がある場合のみ表示）
4. 操作ボタン（下書き保存/確定/出荷/キャンセル/保存）
5. ステータス表示（現在の伝票状態）

## 明細行項目

| #   | 項目名   | 型     | 必須 | 初期値   | バリデーション              | 備考                                 |
| --- | -------- | ------ | ---- | -------- | --------------------------- | ------------------------------------ |
| 1   | 行番号   | number | ○    | 自動採番 | 1から順番                   | システム自動生成                     |
| 2   | 商品ID   | number | ○    | -        | 有効な商品ID                | product_idを参照                     |
| 3   | 商品名   | string | -    | -        | -                           | 選択時に自動表示                     |
| 4   | 予定数量 | number | ○    | -        | 0より大きい整数、最大999999 | 小数点不可                           |
| 5   | 実績数量 | number | -    | -        | 0以上の整数、最大999999     | 未入力時はnull                       |
| 6   | 単位     | string | -    | -        | -                           | 商品マスタから自動取得               |
| 7   | 現在庫数 | number | -    | -        | -                           | 商品選択時に参照表示（リアルタイム） |
| 8   | 備考     | string | -    | -        | 最大500文字                 | 行ごとのメモ                         |

**明細行の制約:**

- 最低1行必須
- 最大100行まで登録可能
- 同一商品の重複登録可（配送先別等の用途）

## 処理仕様

### 1. 新規登録フロー

1. ユーザーが「新規作成」ボタンをクリック
2. 出荷番号を自動採番（SHP-YYYYMMDD-XXXX形式）
3. 出荷日を当日で初期化
4. ステータスを `draft` で初期化
5. ヘッダ情報と明細行を入力
6. 「下書き保存」ボタンで保存（ステータス: draft）

### 2. 確定処理

**条件:**

- ステータスが `draft` であること
- 全明細行の実績数量が入力済みであること

**処理内容:**

1. 入力値のバリデーション
2. 在庫チェック: 各明細行の実績数量 ≤ 現在庫数
   - 在庫不足の場合: 警告メッセージを表示（処理は続行可能）
3. ステータスを `confirmed` に更新
4. 在庫テーブルに対して以下を実行:
   - 対象倉庫 × 商品IDの組み合わせで在庫レコードを検索
   - 現在庫数 - 実績数量 で更新
   - 在庫がマイナスになる場合も更新（警告ログ記録）
5. 確定日時を記録
6. 監査ログに記録

**在庫不足警告の表示例:**

```
⚠ 以下の商品で在庫が不足しています:
- 商品A (ケース): 在庫50、出荷予定95 → 不足45
- 商品C (個): 在庫100、出荷予定150 → 不足50

この状態でも確定できますが、在庫がマイナスになります。
[キャンセル] [確定する]
```

### 3. 出荷完了処理

**条件:**

- ステータスが `confirmed` であること

**処理内容:**

1. ステータスを `shipped` に更新
2. 出荷完了日時を記録
3. 監査ログに記録

**注意:** 出荷完了後は編集・削除が不可となる

### 4. 更新処理

**ステータス別の更新制御:**

- `draft`: 全項目編集可能
- `confirmed`: 実績数量のみ編集可能（差分を在庫に反映）
- `shipped`: 編集不可

**確定済み伝票の実績数量変更時の在庫調整:**

1. 変更前実績数量と変更後実績数量の差分を計算
2. 差分を在庫テーブルに逆算して反映（増加/減少）
3. 変更履歴を監査ログに記録

### 5. 削除処理

**条件:**

- ステータスが `draft` または `confirmed` であること
- ユーザーに削除権限があること（ADMIN系ロールのみ）

**処理内容:**

1. ステータスが `confirmed` の場合、在庫を逆算して戻す
   - 各明細行の実績数量分を在庫に加算
2. 伝票と明細行を論理削除（deleted_at を設定）
3. 監査ログに記録

## 在庫連動

### 確定時の在庫減算ルール

```
確定時:
  在庫不足商品リスト = []

  FOR EACH 明細行 IN 出荷伝票:
    在庫レコード = 在庫テーブル.検索(倉庫ID, 商品ID)
    IF 在庫レコード が存在しない OR 在庫レコード.現在庫数 < 明細行.実績数量:
      在庫不足商品リスト.追加(明細行)

  IF 在庫不足商品リスト が空でない:
    警告メッセージ表示
    ユーザー確認待ち

  IF ユーザーが確定を選択:
    FOR EACH 明細行 IN 出荷伝票:
      在庫レコード = 在庫テーブル.検索(倉庫ID, 商品ID)
      IF 在庫レコード が存在する:
        在庫レコード.現在庫数 -= 明細行.実績数量
        IF 在庫レコード.現在庫数 < 0:
          警告ログ記録（マイナス在庫発生）
      ELSE:
        在庫テーブル.新規作成(
          倉庫ID: 明細行.倉庫ID,
          商品ID: 明細行.商品ID,
          現在庫数: -明細行.実績数量
        )
        警告ログ記録（新規在庫がマイナスで作成）
```

### 実績数量変更時の在庫調整

```
確定済み伝票の実績数量変更時:
  差分 = 変更後実績数量 - 変更前実績数量
  在庫レコード = 在庫テーブル.検索(倉庫ID, 商品ID)
  在庫レコード.現在庫数 -= 差分

  // 増加した場合は在庫が戻る（差分がプラス → マイナスで加算）
  // 減少した場合は在庫が増える（差分がマイナス → マイナスで減算）
```

### 削除時の在庫加算

```
確定済み伝票の削除時:
  FOR EACH 明細行 IN 出荷伝票:
    在庫レコード = 在庫テーブル.検索(倉庫ID, 商品ID)
    在庫レコード.現在庫数 += 明細行.実績数量
```

**在庫更新時の注意点:**

- 在庫更新は全てトランザクション内で実行
- 在庫がマイナスになる場合も処理は続行（警告ログ記録）
- 在庫更新失敗時は伝票ステータス変更もロールバック
- 在庫不足は業務上のアラートであり、システムエラーではない

## 権限

| ロール    | 許可される操作                                 |
| --------- | ---------------------------------------------- |
| WH_USER   | 作成、閲覧、更新（下書き保存、確定、出荷完了） |
| WH_ADMIN  | 作成、閲覧、更新、削除                         |
| OF_USER   | 作成、閲覧、更新（下書き保存、確定、出荷完了） |
| OF_ADMIN  | 作成、閲覧、更新、削除                         |
| SYS_ADMIN | 作成、閲覧、更新、削除                         |

**権限制御の詳細:**

- 削除操作: ADMIN系ロール（WH_ADMIN, OF_ADMIN, SYS_ADMIN）のみ
- 出荷完了後の編集: 全ロール不可
- 他ユーザーの下書き伝票: 閲覧・編集可能（チーム作業を考慮）
- 在庫不足状態での確定: 全ロール可能（警告表示のみ）

## エラーハンドリング

| エラー条件                 | メッセージ                                                            | 挙動                                                    |
| -------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------- |
| 必須項目未入力             | 「出荷日、倉庫、届先は必須項目です」                                  | 400 Bad Request、フォームにエラー表示                   |
| 明細行なし                 | 「明細行を最低1行追加してください」                                   | 400 Bad Request、フォームにエラー表示                   |
| 予定数量が0以下            | 「予定数量は1以上を入力してください」                                 | 400 Bad Request、該当行にエラー表示                     |
| 実績数量が未入力（確定時） | 「確定するには全ての実績数量を入力してください」                      | 400 Bad Request、該当行にエラー表示                     |
| 無効な倉庫ID               | 「指定された倉庫が見つかりません」                                    | 400 Bad Request、フォームにエラー表示                   |
| 無効な商品ID               | 「指定された商品が見つかりません（行番号: X）」                       | 400 Bad Request、該当行にエラー表示                     |
| 無効な運送会社ID           | 「指定された運送会社が見つかりません」                                | 400 Bad Request、フォームにエラー表示                   |
| 在庫不足（確定時）         | 「以下の商品で在庫が不足しています: 商品A（在庫50、出荷95、不足45）」 | 警告表示、確定は可能                                    |
| 伝票番号重複               | 「出荷番号が重複しています」                                          | 409 Conflict、再採番を促す                              |
| 伝票が存在しない           | 「出荷伝票が見つかりません」                                          | 404 Not Found                                           |
| 出荷完了後の編集           | 「出荷完了後の伝票は編集できません」                                  | 409 Conflict、操作を拒否                                |
| 確定済み伝票の再確定       | 「既に確定済みです」                                                  | 409 Conflict、操作を拒否                                |
| 削除権限なし               | 「この操作を行う権限がありません」                                    | 403 Forbidden                                           |
| 在庫更新失敗               | 「在庫の更新に失敗しました」                                          | 500 Internal Server Error、トランザクションロールバック |
| サーバーエラー             | 「サーバーエラーが発生しました」                                      | 500 Internal Server Error、エラーログ記録               |

**エラー表示の原則:**

- フォームレベルのエラー: フォーム上部に赤背景で表示
- フィールドレベルのエラー: 該当フィールドの下に赤文字で表示
- 明細行のエラー: 該当行の該当セルを赤枠で強調
- 在庫不足警告: オレンジ背景の警告バナーで表示（確定は可能）
