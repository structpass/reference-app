## 機能概要

商品の入荷情報を伝票形式で入力・管理する機能。仕入先からの商品受け入れ時に、入荷予定数量と実績数量を記録し、確定時に在庫テーブルへ反映する。下書き保存→確定→完了の3段階ステータス管理により、入荷業務のフローを管理する。

**主な用途:**

- 仕入先からの商品入荷時の受け入れ処理
- 入荷予定と実績の差異管理
- 倉庫別在庫の自動更新

## 明細行項目

| #   | 項目名   | 型     | 必須 | 初期値   | バリデーション              | 備考                   |
| --- | -------- | ------ | ---- | -------- | --------------------------- | ---------------------- |
| 1   | 行番号   | number | ○    | 自動採番 | 1から順番                   | システム自動生成       |
| 2   | 商品ID   | number | ○    | -        | 有効な商品ID                | product_idを参照       |
| 3   | 商品名   | string | -    | -        | -                           | 選択時に自動表示       |
| 4   | 予定数量 | number | ○    | -        | 0より大きい整数、最大999999 | 小数点不可             |
| 5   | 実績数量 | number | -    | -        | 0以上の整数、最大999999     | 未入力時はnull         |
| 6   | 単位     | string | -    | -        | -                           | 商品マスタから自動取得 |
| 7   | 備考     | string | -    | -        | 最大500文字                 | 行ごとのメモ           |

**明細行の制約:**

- 最低1行必須
- 最大100行まで登録可能
- 同一商品の重複登録可（ロット別管理等の用途）

## 処理仕様

### 1. 新規登録フロー

1. ユーザーが「新規作成」ボタンをクリック
2. 入荷番号を自動採番（RCV-YYYYMMDD-XXXX形式）
3. 入荷日を当日で初期化
4. ステータスを `draft` で初期化
5. ヘッダ情報と明細行を入力
6. 「下書き保存」ボタンで保存（ステータス: draft）

### 2. 確定処理

**条件:**

- ステータスが `draft` であること
- 全明細行の実績数量が入力済みであること

**処理内容:**

1. 入力値のバリデーション
2. ステータスを `confirmed` に更新
3. 在庫テーブルに対して以下を実行:
   - 対象倉庫 × 商品IDの組み合わせで在庫レコードを検索
   - 存在する場合: 現在庫数 + 実績数量 で更新
   - 存在しない場合: 新規レコード作成（在庫数 = 実績数量）
4. 確定日時を記録
5. 監査ログに記録

### 3. 完了処理

**条件:**

- ステータスが `confirmed` であること

**処理内容:**

1. ステータスを `completed` に更新
2. 完了日時を記録
3. 監査ログに記録

**注意:** 完了後は編集・削除が不可となる

### 4. 更新処理

**ステータス別の更新制御:**

- `draft`: 全項目編集可能
- `confirmed`: 実績数量のみ編集可能（差分を在庫に反映）
- `completed`: 編集不可

**確定済み伝票の実績数量変更時の在庫調整:**

1. 変更前実績数量と変更後実績数量の差分を計算
2. 差分を在庫テーブルに反映（増加/減少）
3. 変更履歴を監査ログに記録

### 5. 削除処理

**条件:**

- ステータスが `draft` または `confirmed` であること
- ユーザーに削除権限があること（ADMIN系ロールのみ）

**処理内容:**

1. ステータスが `confirmed` の場合、在庫を逆算して戻す
   - 各明細行の実績数量分を在庫から減算
2. 伝票と明細行を論理削除（deleted_at を設定）
3. 監査ログに記録

## 在庫連動

### 確定時の在庫加算ルール

```
確定時:
  FOR EACH 明細行 IN 入荷伝票:
    在庫レコード = 在庫テーブル.検索(倉庫ID, 商品ID)
    IF 在庫レコード が存在する:
      在庫レコード.現在庫数 += 明細行.実績数量
      在庫レコード.更新日時 = 現在時刻
    ELSE:
      在庫テーブル.新規作成(
        倉庫ID: 明細行.倉庫ID,
        商品ID: 明細行.商品ID,
        現在庫数: 明細行.実績数量
      )
```

### 実績数量変更時の在庫調整

```
確定済み伝票の実績数量変更時:
  差分 = 変更後実績数量 - 変更前実績数量
  在庫レコード = 在庫テーブル.検索(倉庫ID, 商品ID)
  在庫レコード.現在庫数 += 差分
```

### 削除時の在庫減算

```
確定済み伝票の削除時:
  FOR EACH 明細行 IN 入荷伝票:
    在庫レコード = 在庫テーブル.検索(倉庫ID, 商品ID)
    在庫レコード.現在庫数 -= 明細行.実績数量
    IF 在庫レコード.現在庫数 < 0:
      警告ログ記録（マイナス在庫発生）
```

**在庫更新時の注意点:**

- 在庫更新は全てトランザクション内で実行
- 在庫がマイナスになる場合も処理は続行（警告ログのみ）
- 在庫更新失敗時は伝票ステータス変更もロールバック

## 権限

| ロール    | 許可される操作                             |
| --------- | ------------------------------------------ |
| WH_USER   | 作成、閲覧、更新（下書き保存、確定、完了） |
| WH_ADMIN  | 作成、閲覧、更新、削除                     |
| OF_USER   | 作成、閲覧、更新（下書き保存、確定、完了） |
| OF_ADMIN  | 作成、閲覧、更新、削除                     |
| SYS_ADMIN | 作成、閲覧、更新、削除                     |

**権限制御の詳細:**

- 削除操作: ADMIN系ロール（WH_ADMIN, OF_ADMIN, SYS_ADMIN）のみ
- 完了済み伝票の編集: 全ロール不可
- 他ユーザーの下書き伝票: 閲覧・編集可能（チーム作業を考慮）

## エラーハンドリング

| エラー条件                 | メッセージ                                       | 挙動                                                    |
| -------------------------- | ------------------------------------------------ | ------------------------------------------------------- |
| 必須項目未入力             | 「入荷日、倉庫、仕入先は必須項目です」           | 400 Bad Request、フォームにエラー表示                   |
| 明細行なし                 | 「明細行を最低1行追加してください」              | 400 Bad Request、フォームにエラー表示                   |
| 予定数量が0以下            | 「予定数量は1以上を入力してください」            | 400 Bad Request、該当行にエラー表示                     |
| 実績数量が未入力（確定時） | 「確定するには全ての実績数量を入力してください」 | 400 Bad Request、該当行にエラー表示                     |
| 無効な倉庫ID               | 「指定された倉庫が見つかりません」               | 400 Bad Request、フォームにエラー表示                   |
| 無効な商品ID               | 「指定された商品が見つかりません（行番号: X）」  | 400 Bad Request、該当行にエラー表示                     |
| 伝票番号重複               | 「入荷番号が重複しています」                     | 409 Conflict、再採番を促す                              |
| 伝票が存在しない           | 「入荷伝票が見つかりません」                     | 404 Not Found                                           |
| 完了済み伝票の編集         | 「完了済みの伝票は編集できません」               | 409 Conflict、操作を拒否                                |
| 確定済み伝票の再確定       | 「既に確定済みです」                             | 409 Conflict、操作を拒否                                |
| 削除権限なし               | 「この操作を行う権限がありません」               | 403 Forbidden                                           |
| 在庫更新失敗               | 「在庫の更新に失敗しました」                     | 500 Internal Server Error、トランザクションロールバック |
| サーバーエラー             | 「サーバーエラーが発生しました」                 | 500 Internal Server Error、エラーログ記録               |

**エラー表示の原則:**

- フォームレベルのエラー: フォーム上部に赤背景で表示
- フィールドレベルのエラー: 該当フィールドの下に赤文字で表示
- 明細行のエラー: 該当行の該当セルを赤枠で強調
