# A-15 グループマスタ詳細入力

## 基本情報

| 項目       | 内容                   |
| ---------- | ---------------------- |
| 機能ID     | A-15                   |
| 機能名     | グループマスタ詳細入力 |
| 画面種別   | 登録/編集/閲覧         |
| ステータス | DONE                   |
| 備考       |                        |

---

## 機能概要

グループ情報の新規登録・編集・閲覧を行う画面。3つのモード（登録/編集/閲覧）を持ち、ロールに応じてアクセス可能なモードが制限される。グループに複数のユーザーを所属させることができ、一括でアクセス制御や権限管理を行うための基盤となる。

## 画面レイアウト

### ヘッダー部

- タイトル:
  - 登録モード: 「グループ新規登録」
  - 編集モード: 「グループ編集」
  - 閲覧モード: 「グループ詳細」
- パンくずリスト: ホーム > グループマスタ一覧 > [現在の画面]

### フォーム部

- 基本情報セクション
  - グループコード、グループ名、説明、ステータス
- 所属ユーザーセクション
  - 所属ユーザー選択エリア（複数選択可能）
  - 選択済みユーザー一覧（削除可能）

### フッター部

- 登録モード: [登録] [キャンセル]
- 編集モード: [保存] [キャンセル]
- 閲覧モード: [編集] [一覧に戻る]（ADMIN系のみ[編集]表示）

## 画面モード

| モード | 説明                           | 遷移条件                                                                   |
| ------ | ------------------------------ | -------------------------------------------------------------------------- |
| 登録   | 新規グループを作成             | A-14一覧画面の[新規登録]ボタンクリック                                     |
| 編集   | 既存グループ情報を更新         | A-14一覧画面の[編集]ボタンクリック、または閲覧モードの[編集]ボタンクリック |
| 閲覧   | グループ情報を表示（入力不可） | A-14一覧画面の行クリックまたは[詳細]ボタンクリック                         |

## 入力項目

| #   | 項目名         | 型           | 必須 | 初期値 | バリデーション                                                 | 備考                             |
| --- | -------------- | ------------ | ---- | ------ | -------------------------------------------------------------- | -------------------------------- |
| 1   | グループコード | string       | ○    | -      | 半角英数字・ハイフン・アンダースコア、2-50文字、一意性チェック | group_code、登録後は変更不可     |
| 2   | グループ名     | string       | ○    | -      | 1-100文字                                                      | name                             |
| 3   | 説明           | textarea     | -    | -      | 0-500文字                                                      | description                      |
| 4   | 所属ユーザー   | multi-select | -    | []     | 存在するユーザーIDのみ                                         | members、複数選択可能            |
| 5   | ステータス     | select       | ○    | active | active/inactive                                                | status、ラジオボタンまたはトグル |

### ステータス選択肢

- `active`: 有効
- `inactive`: 無効

## 所属ユーザー管理

### ユーザー追加

1. [ユーザーを追加] ボタンクリックでユーザー選択モーダルを表示
2. モーダル内で検索可能（ユーザーID/ユーザー名で部分一致検索）
3. チェックボックスで複数ユーザーを選択
4. [追加] ボタンクリックで選択済みユーザー一覧に追加
5. 既に追加済みのユーザーは選択不可（グレーアウト）

### ユーザー削除

1. 選択済みユーザー一覧の各行に[削除]アイコンを表示
2. [削除]アイコンクリックで該当ユーザーを一覧から除外
3. 確認ダイアログは表示せず即座に削除（保存前なので元に戻せる）

### 選択済みユーザー一覧表示項目

- ユーザーID
- ユーザー名
- ロール（日本語表示）
- ステータス（バッジ表示）
- 操作（削除アイコン）

## 処理仕様

### 登録モード

#### 初期表示

1. 全フィールドを空欄で表示
2. ステータスのデフォルト値: active
3. 所属ユーザーは空（未選択）

#### バリデーション（リアルタイム）

1. グループコード: 入力時に形式チェック、フォーカスアウト時に一意性チェック
2. グループ名: 入力時に文字数チェック
3. 説明: 入力時に文字数チェック（500文字でカウンター表示）

#### 登録処理

1. [登録]ボタンクリック時に全フィールドのバリデーション実行
2. エラーがある場合は最初のエラーフィールドにフォーカス
3. バリデーション成功時、POST APIを実行
4. 成功時: 成功トースト表示、A-14一覧画面に遷移
5. 失敗時: エラートースト表示、画面維持

### 編集モード

#### 初期表示

1. APIから指定IDのグループ情報を取得
2. 取得したデータを各フィールドに設定
3. グループコードフィールドは読み取り専用（disabled）
4. 所属ユーザー一覧を表示

#### 更新処理

1. [保存]ボタンクリック時に変更されたフィールドのバリデーション実行
2. バリデーション成功時、PUT APIを実行
3. 所属ユーザーの変更（追加・削除）も同時に送信
4. 成功時: 成功トースト表示、A-14一覧画面に遷移
5. 失敗時: エラートースト表示、画面維持

### 閲覧モード

#### 初期表示

1. APIから指定IDのグループ情報を取得
2. 全フィールドを読み取り専用で表示
3. 所属ユーザー一覧を表示（[削除]アイコンは非表示）
4. ADMIN系ロールの場合は[編集]ボタン表示

#### 編集モード遷移

1. [編集]ボタンクリック時に編集モードに切替
2. URLを `/groups/:id/edit` に変更

## API

| メソッド | エンドポイント     | 説明                                             |
| -------- | ------------------ | ------------------------------------------------ |
| GET      | /api/v1/groups/:id | 指定グループ情報を取得                           |
| POST     | /api/v1/groups     | 新規グループを登録                               |
| PUT      | /api/v1/groups/:id | 既存グループ情報を更新                           |
| DELETE   | /api/v1/groups/:id | 指定グループを削除（一覧画面から実行）           |
| GET      | /api/v1/users      | ユーザー一覧を取得（所属ユーザー追加モーダル用） |

### リクエスト例（POST /api/v1/groups）

```json
{
  "group_code": "WH_A",
  "name": "倉庫Aグループ",
  "description": "倉庫A担当者のグループです。入出荷業務を担当します。",
  "members": ["user001", "user002", "user003"],
  "status": "active"
}
```

### リクエスト例（PUT /api/v1/groups/:id）

```json
{
  "name": "倉庫Aグループ（更新）",
  "description": "倉庫A担当者のグループです。入出荷業務と棚卸業務を担当します。",
  "members": ["user001", "user004"],
  "status": "active"
}
```

## 権限

| ロール    | 許可される操作                      |
| --------- | ----------------------------------- |
| SYS_ADMIN | CRUD（全モードアクセス可能）        |
| WH_ADMIN  | CRUD（全モードアクセス可能）        |
| OF_ADMIN  | CRUD（全モードアクセス可能）        |
| WH_USER   | R（閲覧モードのみ、登録・編集不可） |
| OF_USER   | R（閲覧モードのみ、登録・編集不可） |

所属（メンバー）の追加・削除には、上記に加えて次の制限がかかる。所属は掲示の公開範囲（宛先グループ）を決めるため、所属を足せる経路はそのまま閲覧権限の付与になる。

- **編成できるグループは、そのグループのロール系統まで。** グループの系統は `role` の値で決まり、倉庫系統は `WH_ADMIN` / `WH_USER` / `SYS_ADMIN`（未設定は既定の `WH_USER`）、事務系統は `OF_ADMIN` / `OF_USER`。倉庫系統なら WH_ADMIN、事務系統なら OF_ADMIN が編成する。系統をまたぐ追加・削除は SYS_ADMIN 以外できない（例: OF_ADMIN は倉庫チームのグループを編成できない）。
- **系統をまたぐ `role` の変更（例: `OF_USER` → `WH_USER`）と、系統をまたぐ `role` を指定した新規作成は SYS_ADMIN だけができる。** 編成の範囲が `role` で決まるため、範囲の外の者が `role` を指定して境界をすり抜けられないようにしている。同じ系統の中での変更（`WH_USER` ↔ `WH_ADMIN`）と、自分の系統のグループの作成は従来どおりできる。
- **グループの変更（名前・コード・ステータスを含む）は、そのグループを編成できる側だけができる。** 系統をまたぐ変更は、`role` を変えないものでも SYS_ADMIN 以外できない（例: OF_ADMIN は倉庫チームのグループを無効化できない）。編成・作成と同じ「そのグループを扱えるか」の1つの基準に揃えている。
- 一般ユーザー（WH_USER / OF_USER）はグループを編成しない（編成は管理者の役割）。所属の追加・削除に必要な権限（`groups:update`）も既定では持たない。
- 自分自身の追加は SYS_ADMIN 以外できない（宛先グループへ自分を足して、本来読めない掲示を読む経路を塞ぐ）。
- SYS_ADMIN 領域（`role=SYS_ADMIN` のグループ、SYS_ADMIN ロールのユーザー）の所属変更は SYS_ADMIN 以外できない。ユーザーマスタの権限付与境界（SYS_ADMIN アカウントは SYS_ADMIN だけが扱える）と同じ境目。
- **画面の追加候補には、自分自身と SYS_ADMIN ロールのユーザーを出さない**（選ぶと必ず拒否される候補を提示しない）。呼び出し元が SYS_ADMIN の時も同じ基準で外す（API は SYS_ADMIN に許可しているが、画面は候補を絞る側に倒す）。
- **編成できない系統のグループでは、追加候補と追加ボタンを出さない。** 呼び出し元の系統とグループの系統（`Group.role`）が違う場合（例: OF_ADMIN が倉庫系統のグループを開く）は、その旨と依頼先（システム管理者）を画面に出し、追加の操作は提示しない（選ぶと必ず 403 になる候補を並べない。グループの `role` が取得できていない時も候補を出さない側に倒す）。閲覧モード（`readonly`）では理由も出さない（元から操作が無いため）。系統の判定は画面側にも同じ表を持ち、サーバーの `canOrganizeGroup` と一致させる。
- 追加・削除・グループ削除が拒否された時は、汎用の文言ではなく API が返した理由をトーストに表示する。
- 自分自身の削除は制限しない（可視範囲が狭まるだけで、権限の昇格にならない）。
- グループの登録・編集で `role` を `SYS_ADMIN` にする操作、および `role=SYS_ADMIN` のグループの編集・削除は SYS_ADMIN だけができる。所属変更の境界はグループの `role` を前提にするため、同じ権限で前提を書き換えられないようにしている。
- **依存データが残るグループは削除できない**（`409`）。掲示の宛先になっている場合（宛先が消えるとその掲示が全ユーザーへ公開される状態に変わるため。宛先の変更は SYS_ADMIN のみ）と、所属ユーザーが残っている場合（先に所属を外す）で、理由を出し分ける。

### 誰が誰を編成できるか

呼び出し元のロール × 宛先グループの系統で決まる。グループの系統は `role` が倉庫系統（`WH_ADMIN` / `WH_USER` / `SYS_ADMIN`。未設定は既定の `WH_USER`）なら WH、事務系統（`OF_ADMIN` / `OF_USER`）なら OF。

| 呼び出し元 | WH 系統のグループ | OF 系統のグループ | SYS_ADMIN のグループ |
| ---------- | ----------------- | ----------------- | -------------------- |
| SYS_ADMIN  | 追加・削除 可     | 追加・削除 可     | 追加・削除 可        |
| WH_ADMIN   | 追加・削除 可     | 不可（403）       | 不可（403）          |
| OF_ADMIN   | 不可（403）       | 追加・削除 可     | 不可（403）          |
| WH_USER    | 不可（403）       | 不可（403）       | 不可（403）          |
| OF_USER    | 不可（403）       | 不可（403）       | 不可（403）          |

同じ系統の管理者どうしの追加・削除（例: WH_ADMIN が別の WH_ADMIN を WH 系統のグループへ足す）は通る。編成の委任であり、塞ぐと自分の系統のグループへ人を足せなくなるため受容している。同じ系統でも所属の異なるグループへ足せば掲示の可視範囲は広がるため、これは権限の付与である（受容した穴。理由と限界は判断記録を参照）。

## エラーハンドリング

| エラー条件                | メッセージ                                                                                                                                         | 挙動                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 必須フィールド未入力      | 「{フィールド名}は必須です」                                                                                                                       | 該当フィールド下にエラー表示、フォーカス移動 |
| グループコード形式不正    | 「グループコードは半角英数字・ハイフン・アンダースコアで2-50文字で入力してください」                                                               | 該当フィールド下にエラー表示                 |
| グループコード重複（409） | 「このグループコードは既に使用されています」                                                                                                       | 該当フィールド下にエラー表示                 |
| グループ名超過            | 「グループ名は100文字以内で入力してください」                                                                                                      | 該当フィールド下にエラー表示                 |
| 説明超過                  | 「説明は500文字以内で入力してください（現在: {文字数}文字）」                                                                                      | 該当フィールド下にエラー表示                 |
| グループ不存在（404）     | 「指定されたグループが見つかりません」                                                                                                             | エラートースト表示、一覧に戻る               |
| 権限不足（403）           | 「この操作を実行する権限がありません」                                                                                                             | エラートースト表示、一覧に戻る               |
| 編成範囲外（403）         | 「担当系統の異なるグループは編成できません（このグループは倉庫担当の管理者が編成します）。変更が必要な場合はシステム管理者へご依頼ください」       | エラートースト表示、画面維持                 |
| 所属変更の拒否（403）     | 「自分自身をグループへ追加することはできません」「システム管理者の所属変更はシステム管理者のみ実行できます」（API が返した理由をそのまま表示）     | エラートースト表示、画面維持                 |
| 系統変更の権限不足（403） | 「グループの担当系統を変更できるのはシステム管理者のみです。変更が必要な場合はシステム管理者へご依頼ください」                                     | エラートースト表示、画面維持                 |
| 系統違いの作成（403）     | 「担当系統の異なるグループは作成できません（事務担当のグループは事務担当の管理者が作成します）。変更が必要な場合はシステム管理者へご依頼ください」 | エラートースト表示、画面維持                 |
| サーバーエラー（500）     | 「グループ情報の保存に失敗しました。時間をおいて再度お試しください」                                                                               | エラートースト表示、画面維持                 |
| ネットワークエラー        | 「通信エラーが発生しました。ネットワーク接続を確認してください」                                                                                   | エラートースト表示、画面維持                 |
