| 項目       | 内容                                             |
| ---------- | ------------------------------------------------ |

## 機能概要

ロールに対して機能ごとの参照・登録・修正・削除の可否を設定する画面。サイドバーに出る機能を一覧し、ロール単位で権限を切り替える。ユーザー単位・グループ単位の設定は持たない（未実装。末尾「未実装の仕様」を参照）。

設定した値はロールの既定権限を置き換え、対象ロールの利用者が次にアクセスした時から適用される。

## 画面レイアウト

### ヘッダー部

- タイトル: 「機能別権限設定」
- [権限を保存] ボタン: 変更がある時だけ有効

### マトリクステーブル

- 縦軸（行）: 機能（カテゴリごとにグループ化。18 機能＋ユーザー定義台帳）
- 横軸（列）: ロール（倉庫(一般) / 倉庫(管理) / 事務(一般) / 事務(管理) / システム管理）
- 各セル: 参照・登録・修正・削除の4ボタン。色付き=ON、グレー=OFF
- SYS_ADMIN 列は「(常にON)」の表示で、操作できない
- 当該機能に無い操作はセル自体を表示しない（例: 一覧専用の機能は参照のみ）
- SYS_ADMIN 専用機能は、他ロールのセルを固定 OFF で表示し、操作できない
- 機能名の後ろに「(閲覧専用)」を付ける機能がある（登録の可否を持たない機能）

### フッター部

- 凡例: 参照(R) / 登録(C) / 修正(U) / 削除(D)、色付き=ON・グレー=OFF

## 処理仕様

### 初期表示

1. ロール別の権限行と、台帳カタログ（非プリセットの ObjectType）を同じ世代で取得する
2. 全機能×全ロールを既定値（SYS_ADMIN のみ全 ON、他ロールは全 OFF）で初期化し、取得した権限行で上書きする
3. SYS_ADMIN 専用機能は、DB に不整合な権限行が残っていても SYS_ADMIN のみ全 ON・他ロール全 OFF を維持する

### セル操作

1. SYS_ADMIN の列と、SYS_ADMIN 専用機能のセルは操作できない
2. ユーザー定義台帳の行は、参照を OFF にすると登録・修正・削除も OFF になる
3. 変更があると [権限を保存] が有効になる

### 保存処理

1. 全機能×全ロールの4可否を組み立てる
2. `PUT /api/v1/permissions/roles` へ送信する（部分上書きではなく、4可否の全置換）
3. 成功時: 「権限を保存しました」を表示する
4. 失敗時: 「権限の保存に失敗しました」を表示する

### 取得失敗時

1. マトリクスを描画しない
2. 「権限情報を読み込めないため、保存できません。」を表示し、保存もできない

## API

画面が使う API:

| メソッド | エンドポイント                     | 説明                                                   |
| -------- | ---------------------------------- | ------------------------------------------------------ |
| GET      | /api/v1/permissions/roles          | ロール別の権限マトリクスを取得（SYS_ADMIN のみ）       |
| PUT      | /api/v1/permissions/roles          | ロール別の権限を一括保存（SYS_ADMIN のみ）             |
| GET      | /api/v1/permissions/my-permissions | 自分の有効権限を取得（全認証ユーザー。メニュー表示用） |

ユーザー単位・グループ単位の旧 API（`/api/v1/permissions/user/:userId`・`/api/v1/permissions/group/:groupId` 系の 6 本）は撤去済み。画面から呼ばれておらず、有効権限の解決にも使われない経路だったため。

### リクエスト例（PUT /api/v1/permissions/roles）

```json
{
  "permissions": [
    {
      "role": "WH_USER",
      "featureId": "products",
      "canView": true,
      "canCreate": false,
      "canUpdate": false,
      "canDelete": false
    }
  ]
}
```

### レスポンス例（GET /api/v1/permissions/roles）

```json
{
  "success": true,
  "data": [
    {
      "id": "3f1c0b8e-6a2d-4c1f-9b7a-2d5e8f0a1b23",
      "role": "WH_USER",
      "featureId": "products",
      "canView": true,
      "canCreate": false,
      "canUpdate": false,
      "canDelete": false
    }
  ]
}
```

## 権限

| ロール        | 許可される操作                                                        |
| ------------- | --------------------------------------------------------------------- |
| SYS_ADMIN     | 画面の閲覧と権限の保存（API も SYS_ADMIN 固定）                       |
| その他4ロール | 既定では不可（`permissions` は SYS_ADMIN 専用機能で参照可否が false） |

## 未実装の仕様

- ユーザー単位・グループ単位の権限設定は未実装。画面も API も無く、有効権限の解決はロール別の既定値・ロール別の権限行（`RolePermission`）・ユーザー定義台帳（非プリセット ObjectType）の動的権限で決まる
- この単位を実装する場合は、画面・API・有効権限の解決を一組で設計し、本節を仕様へ書き換える

## エラーハンドリング

実装の挙動:

| エラー条件     | 挙動                                                                                   |
| -------------- | -------------------------------------------------------------------------------------- |
| 権限の取得失敗 | マトリクスを描画せず「権限情報を読み込めないため、保存できません。」を表示。保存も不可 |
| 権限の保存失敗 | 「権限の保存に失敗しました」を表示し、画面は維持する                                   |
| 権限不足       | API は 403。画面は参照可否の判定で別画面へ遷移する                                     |
