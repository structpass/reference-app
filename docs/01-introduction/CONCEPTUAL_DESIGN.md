## この会社は何をしているか

**倉庫管理委託業** — 荷主から商品を預かり、倉庫で保管し、指示に応じて出荷する。

この業務の中核は「在庫」です。在庫が正確であることが、すべての業務の前提になります。

---

## 業務の全体フロー

```
                    ┌─────────┐
                    │  発注   │  仕入先に商品を注文する
                    │ (Order) │
                    └────┬────┘
                         │ 発注した商品が届く
                         ▼
┌─────────┐       ┌─────────┐       ┌─────────┐
│ 仕入先  │──────▶│  入荷   │──────▶│  在庫   │
│(Supplier)│       │(Receiving)│  +加算  │ (Stock) │
└─────────┘       └─────────┘       └────┬────┘
                                         │
                         ┌───────────────┤
                         │               │
                         ▼               ▼
                  ┌─────────┐     ┌──────────┐
                  │  出荷   │     │  棚卸    │
                  │(Shipment)│     │(Stocktaking)│
                  └────┬────┘     └─────┬────┘
                   -減算│           ±調整│
                       ▼               ▼
                  ┌─────────┐     ┌──────────┐
                  │ 届け先  │     │ 在庫調整  │
                  │(顧客)   │     │  ログ    │
                  └─────────┘     └──────────┘
```

### 日常業務のサイクル

1. **発注** — 在庫が少なくなった商品を仕入先に注文する（事務担当）
2. **入荷** — 届いた商品を検品し、倉庫に入れる（倉庫担当）→ 在庫が増える
3. **保管** — 在庫状況を確認し、予測在庫を管理する（事務担当）
4. **出荷** — 出荷指示に基づいて商品を倉庫から出す（倉庫担当）→ 在庫が減る
5. **棚卸** — 定期的に実際の在庫を数え、システムと照合する（倉庫担当）→ 差異を調整

## 在庫の増減ルール

在庫（`stocks` テーブル）は、倉庫 × 商品 の組み合わせごとに数量を持ちます。

```
在庫 = 倉庫A の 商品X が 何個あるか
```

### いつ増え、いつ減るか

| イベント     | 在庫への影響               | タイミング                     |
| ------------ | -------------------------- | ------------------------------ |
| **入荷確定** | **＋加算**（実績数量分）   | 入荷伝票を「確定」した時       |
| **出荷確定** | **−減算**（実績数量分）    | 出荷伝票を「確定」した時       |
| **棚卸確定** | **±調整**（差異分）        | 棚卸を「確定」した時           |
| **手動調整** | **±調整**                  | システム管理者が直接操作した時 |
| **伝票削除** | **逆算**（確定済みの場合） | 確定済み伝票を削除した時       |

すべての在庫変更は `stock_adjustments` テーブルに記録されます。変更前の数量、変更後の数量、理由、誰が操作したかが追跡可能です。

### 画面の標準パターン

すべての機能は、2つのパターンのいずれかに従います。

#### パターン1: マスタ管理（一覧 + CRUD）

```
一覧画面
├── [新規登録] → 新規画面（フォーム）→ 保存 → 一覧に戻る
├── [行クリック] → 詳細画面（読み取り専用）→ [編集] → 編集画面
├── [検索] → 一覧をフィルタリング
├── [Excel出力] → ファイルダウンロード
└── [削除] → 確認ダイアログ → 削除 → 一覧を更新
```

#### パターン2: 伝票入力（ヘッダ + 明細行）

```
一覧画面
├── [新規登録] → 伝票画面
│     ├── ヘッダ（日付、倉庫、仕入先/宛先 等）
│     ├── 明細行テーブル（商品、予定数、実績数）
│     │     ├── [+ 行追加]
│     │     └── [行削除]
│     ├── [下書き保存] → ステータス: DRAFT
│     ├── [確定] → ステータス: CONFIRMED → 在庫に反映
│     └── [完了] → ステータス: COMPLETED
├── [行クリック] → 伝票詳細（読み取り専用）
└── [Excel出力] → ファイルダウンロード
```

## ステータス遷移

伝票系の機能は、すべて同じライフサイクルに従います。

### 入荷（Receiving）

```
DRAFT ──────▶ CONFIRMED ──────▶ COMPLETED
下書き         確定（在庫+加算）    完了
  │
  └── 削除可（在庫影響なし）
               └── 削除可（在庫を逆算して戻す）
```

### 出荷（Shipment）

```
DRAFT ──────▶ CONFIRMED ──────▶ SHIPPED
下書き         確定（在庫-減算）    出荷済み
  │
  └── 削除可（在庫影響なし）
               └── 削除可（在庫を逆算して戻す）
```

### 発注（Order）

```
DRAFT ──▶ ORDERED ──▶ PARTIALLY_RECEIVED ──▶ COMPLETED
下書き     発注済み     一部入荷              全量入荷完了
```

### 棚卸（Stocktaking）

```
DRAFT ──────▶ CONFIRMED
下書き         確定（在庫±調整、調整ログ記録）
```

### 共通ルール

- **DRAFT**: 自由に編集・削除できる。在庫への影響なし
- **CONFIRMED 以降**: 在庫に反映済み。削除する場合は在庫を逆算して戻す
- **ステータスは後戻りしない**: CONFIRMED → DRAFT には戻れない
